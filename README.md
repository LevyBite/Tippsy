## Why Tippsy

Tippsy makes a small everyday task effortless: calculating the right tip and splitting a bill with friends. It focuses on clarity, accessibility, and delightful micro-interactions — spend less time doing math and more time enjoying the table.

## Features

- Clean, responsive UI with light/dark themes
- Preset tip buttons + custom percentage + fine‑tune slider
- Split bills across people with quick picks and stepper
- Round‑up per‑person option and visible rounding impact
- Animated numbers for smooth feedback
- Share the split (clipboard + Web Share API)
- No account required — state is stored locally in the browser

## How to contribute (fast & friendly)

1. Fork or create a branch (suggested branch name: `readme-improve` or `fix/your-thing`).
2. Run locally: `npm install && npm run dev` to test changes.
3. Keep commits focused (one idea per commit / PR).
4. For UI changes: include before/after screenshots or a short GIF (put media in `media/`).
5. Open a Draft PR targeting `main` for feedback, and include a short description of what you changed and how you tested it.
6. Use small, descriptive PR titles (example: `feat: add quick-picks` / `fix: rounding calculation`).


## Deploy (Vercel) — simple explanation

Vercel is the hosting service used for the live preview. Think of it like an automated builder and host: push code to GitHub, Vercel builds it and serves the site for you.

Quick deploy steps:
1. Connect this GitHub repo to Vercel (https://vercel.com) and pick the default branch.
2. Vercel will detect Next.js and create the build automatically.
3. On every push to the default branch Vercel will rebuild and redeploy.

If you want to customize builds or redirects, create a `vercel.json` or set settings in the Vercel dashboard.

## Pull Requests (PRs) — baby explanation

A PR is how you propose changes: create a branch, push your commits, open a PR to discuss and merge. Use a Draft PR when you want feedback but aren’t ready to merge.
